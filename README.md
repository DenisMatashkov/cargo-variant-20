# Визуализация зависимостей Cargo

Практическая работа по конфигурационному управлению, вариант 20.
Инструмент на Python читает метаданные пакетов Rust из индекса crates.io.

## Настройки

По умолчанию используется `config.xml`. Путь к другому XML можно
передать первым аргументом. Путь к локальному графу считается от XML.

| Параметр | Назначение |
| --- | --- |
| `package` | Имя пакета. В тестовом режиме используются буквы A–Z. |
| `repository` | HTTP(S)-адрес индекса Cargo или путь к тестовому файлу. |
| `test_mode` | Тестовый режим. Допустимы `true` и `false`. |
| `version` | Точная версия пакета, например `1.11.1`. |
| `output` | Имя файла SVG. Зарезервированные имена Windows запрещены. |
| `ascii_tree` | Вывод ASCII-дерева. Допустимы `true` и `false`. |
| `max_depth` | Максимальная глубина. `0` означает только корень. |
| `filter_substring` | Подстрока для исключения пакетов. Пустое поле отключает фильтр. |

Относительный путь к тестовому файлу считается от папки с XML.

`load_config()` читает и проверяет настройки. `validate_repository()`
проверяет URL или путь, а `validate_output_name()` отклоняет имена
вроде `NUL.svg` и `CON.svg`.

## Запуск и тесты

Для запуска нужен Python 3.10 или новее. Отдельная сборка и установка
библиотек не требуются. Выполни из корня проекта в PowerShell.

```powershell
.\run.bat
py -3 -B -m unittest discover -s tests -v
```

## Чтение индекса Cargo

- `index_path()` определяет путь в индексе, например `re/ge/regex`.
- `read_index()` читает по HTTP(S) JSON-записи версий пакета.
- `find_release()` находит точную версию среди загруженных записей.
- `get_release()` загружает записи и возвращает нужную версию.

## Построение графа

`collect_graph()` выбирает индекс или локальный файл. `build_graph()`
строит список смежности обходом BFS с очередью. Он учитывает глубину,
фильтр и циклы. В тестовом графе ребро `D -> A` замыкает цикл.
При глубине 1 видны `A`, `B` и `C`. Фильтр `D` исключает `D`
из обеих веток.

| Источник и метод | Назначение |
| --- | --- |
| `CargoSource.__init__()` | Запоминает адрес индекса и создаёт кеш. |
| `CargoSource.records()` | Загружает записи или читает их из кеша. |
| `CargoSource.release()` | Находит запись нужной версии пакета. |
| `CargoSource.requirements()` | Читает обычные и сборочные зависимости. |
| `CargoSource.resolve()` | Выбирает подходящую версию зависимости. |
| `TestSource.__init__()` | Читает локальный список смежности. |
| `TestSource.add_line()` | Разбирает строку вида `A: B C`. |
| `TestSource.validate_references()` | Проверяет ссылки на соседние вершины. |
| `TestSource.check_package()` | Проверяет наличие пакета в файле. |
| `TestSource.requirements()` | Возвращает соседей тестовой вершины. |
| `TestSource.resolve()` | Возвращает пустую версию тестового пакета. |

| Подбор версии | Назначение |
| --- | --- |
| `version_key()` | Строит ключ сравнения версий SemVer. |
| `parse_term()` | Разбирает одно условие на версию. |
| `compare_version()` | Сравнивает версии по операторам вроде `>=`. |
| `matches_term()` | Проверяет выполнение одного условия. |
| `matching_versions()` | Отбирает подходящие версии, пропуская отозванные. |
| `newest_version()` | Возвращает максимальную подходящую версию. |

Граф включает объявленные обычные и сборочные зависимости, в том
числе необязательные и платформенные. Версия выбирается для
каждого требования отдельно. Cargo дополнительно учитывает
активированные возможности, платформу и `Cargo.lock`.

`main()` запускает анализ, `print_graph()` печатает список смежности,
а `package_label()` формирует подпись вершины.

```powershell
.\run.bat tests\config_graph.xml
```

## Этап 4. Порядок загрузки зависимостей

`reverse_edges()` находит пакеты, использующие каждую зависимость.
`calculate_load_order()` возвращает топологический порядок и пакеты,
заблокированные циклом. На этапе 4 `print_load_order()` печатает
порядок без исходного пакета.

| Глубина | Фильтр | Результат на тестовом графе |
| --- | --- | --- |
| 3 | Пустой | Выводится E. Цикл блокирует A, B, C и D. |
| 2 | Пустой | D, E, B, C |
| 3 | D | B, E, C |

### Сравнение с Cargo

Проверка выполнена в Cargo 1.100.0 в отдельном проекте
с зависимостью `regex = "=1.11.1"`. Команда `cargo fetch -v`
с пустым кэшем вывела строки `Downloaded` в таком порядке:

```text
memchr 2.8.3
aho-corasick 1.1.5
regex 1.11.1
regex-syntax 0.8.11
regex-automata 0.4.18
```

Наша программа вывела 12 зависимостей. Четыре общих пакета шли
в порядке `memchr`, `regex-syntax`, `aho-corasick`, `regex-automata`.

Программа вычисляет порядок по рёбрам графа: зависимость должна
предшествовать использующему её пакету. Cargo может скачивать
архивы параллельно, поэтому порядок строк `Downloaded` зависит
от завершения загрузок. `regex` попал в журнал Cargo, потому что
для проверочного проекта он сам является зависимостью.

В граф программы входят объявленные необязательные зависимости,
в том числе `log` и `arbitrary`. Cargo при проверке с настройками
по умолчанию их не активировал. Это видно в `cargo tree`.


Для вывода порядка укажи `--load-order`.

```powershell
.\run.bat tests\config_graph.xml --load-order
.\run.bat --load-order
```
